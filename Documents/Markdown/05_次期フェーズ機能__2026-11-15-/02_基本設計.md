# 基本設計書：ノート・アーカイブCSV横断 キーワード該当行抽出機能

## 1. システム構成・ファイル配置設計

### 1.1 対象ディレクトリおよび新規・改修ファイル一覧

さくらレンタルサーバー（PHP + MySQL + CDN版Vue.js/Vuetify）の既存アーキテクチャを踏襲し、以下の構成で新規作成および既存改修を行う。

| 区分 | ファイルパス | 役割・概要 | 
| :--- | :--- | :--- | 
| **改修** | `SourceCodes/pages/index.php` | ログイン後ヘッダー（`header-right`）のログアウトアイコン左隣に、本機能ページを別タブで開くアイコンを追加する。 | 
| **新規** | `SourceCodes/pages/keywordLinesSearch/index.php` | 本機能のメイン画面（PHPによるセッション判定＋CDN読み込み＋`<script type="module">` でのVueインスタンスマウント）。 | 
| **新規** | `SourceCodes/static/keywordLinesSearch.css` | 本機能専用の青テイスト配色および3段階ステップUI・並び替えバー・ハイライト装飾用スタイルシート。 | 
| **新規** | `SourceCodes/static/js/components/keywordLinesSearchApp.js` | 本機能のメインVueコンポーネント（`<script type="module">` から `import` して `Vue.component()` 登録。Step 1〜3の状態管理、検索実行、チェック選択・リセット、並び替え制御、コピー・ダウンロード処理）。 | 
| **新規** | `SourceCodes/server/api/getKeywordLinesList.php` | DB（`ulinker_notes`）および選択されたCSV（`ulinker_notes*.csv`）を `contents_id` 昇順で横断検索し、権限フィルタ・アンエスケープ後にキーワード該当行を抽出して返却するAPI。 | 
| **流用** | `SourceCodes/server/api/getCsvList.php` | **新規APIは作成せず既存APIをそのまま流用**し、`SourceCodes/storage/csv/` 配下のCSVファイル名一覧を取得した上で、Vue側にて `startsWith('ulinker_notes')` で絞り込む。 | 

**【実装上の重要留意事項】**

* **CSS・静的リソースの相対パス補正**：`SourceCodes/pages/keywordLinesSearch/index.php` は `pages/` より1階層深いため、既存 `properties.php` の `HEAD_LINKS` にある相対パス（`../static/style.css`）をそのまま出力するとパス不整合となる。本ページでは `../../static/style.css` および `../../static/keywordLinesSearch.css` を適切に読み込む構成とする。
* **二重アンエスケープの防止**：アンエスケープ処理（`&nbsp;` → 半角スペース、`&#39;` → `'` 等への復元）はサーバー側（PHP）で完結させてレスポンスを返却する。フロントエンド（Vue側）で既存の `commonFunctions.unescapeText()` を重ねて実行すると、本文中に元から含まれていたエスケープ表記等が誤変換されるリスクがあるため、**フロント側での再アンエスケープは行わず**、PHPから返却された文字列をそのまま使用する。

## 2. 画面遷移・外部インターフェース設計

### 2.1 既存画面（`pages/index.php`）からの起動導線

* **配置位置**：ログイン状態（`sessionString !== ''`）の `<div class="header-right">` 内において、既存のログアウトアイコン（`mdi-logout`）の**左隣**に配置する。
* **アイコン仕様**：

  * ツールチップ（`title`属性）：`ノート・CSVキーワード該当行一覧検索を別タブで開きます`
  * 挙動：クリック時、`window.open('./keywordLinesSearch/index.php', '_blank')`（または `<a href="./keywordLinesSearch/index.php" target="_blank" rel="noopener noreferrer">`）により新規タブで起動する。

### 2.2 未ログインアクセス時の制御フロー

1. `pages/keywordLinesSearch/index.php` の初期表示時、既存 `pages/index.php` と同一のPHPセッション変数を確認する。
   * ログイン状態判定：`isset($_SESSION['session_string']) && $_SESSION['session_string'] !== ''`
   * ユーザー情報取得：`$_SESSION['owner_id']`（ログインユーザーID）、`$_SESSION['is_teacher']`（講師フラグ）
2. 未ログイン状態と判定された場合：
   * Step 1〜3の検索UIは一切描画しない（PHP分岐によりコンポーネントマウント自体を抑止）。
   * 画面中央にエラーメッセージカードを表示する（例：「ログイン状態が確認できませんでした。U-Linker本体の画面からログインした状態で再度アクセスしてください。」＋トップページ `../index.php` へのリンクボタン）。
3. ログイン済みと判定された場合：
   * 既存 `pages/index.php` と同様にAPI通信用のワンタイムトークン（半角英数字16文字 `token`）およびユーザー情報（`owner_id`, `is_teacher`）をフロントエンドへ引き渡す。

### 3.2 3段階ステップUI＋並び替えバー構成

#### 【Step 1】キーワード検索エリア（初期表示）

初期ロード時はヘッダーと本エリアのみが表示される。

1. **検索キーワード入力欄**：
   * 1行テキスト入力（プレースホルダー：`検索したいキーワードを1つ入力（スペース区切り時は先頭1語のみ有効）`）。
   * 検索実行時、入力文字列の前後空白をトリムし、半角・全角スペースで分割した**先頭の1要素のみ**を検索キーワードとして確定する。
2. **検索対象ソース選択テーブル**：
   * 画面初期表示時に既存API `../../server/api/getCsvList.php` を呼び出し、取得したファイル名一覧から `fileName.startsWith('ulinker_notes')` に該当するCSVファイルのみを抽出する。
   * 既存 `searchForm.js` に準拠し、先頭行に「DB（`ulinker_notes`）」、以降に抽出した `ulinker_notes*.csv` ファイル一覧をチェックボックス付きテーブルで表示する。
   * 選択可能数：**1件以上〜4件以内**（初期状態およびリセット時は**未選択（チェックなし）**）。
3. **最大取得件数プルダウン**：
   * 選択肢：`10` / `50` / `100` / `500`（デフォルト：最小の `10`）。
   * 選択された複数ソース全体を通して「ヒットするノート（レコード）の最大件数」の上限として機能する。
4. **操作ボタン**：
   * 中央寄りに配置する（視認性・操作性向上）。
   * ボタンの文字色は明瞭な白（`#FFFFFF`）とする。
   * **「検索」ボタン**：キーワード未入力またはソース未選択時はバリデーションメッセージを表示。正常時は検索APIを呼び出し、**Step 2** を表示する（再検索時はStep 2のチェック状態を全未チェックにし、並び替えバーおよび Step 3 を一旦閉じる）。
   * **「リセット」ボタン**：検索キーワード、ソース選択状態（チェックなし）、最大取得件数（`10`）、並び替えプルダウンを初期値に戻し、Step 2・並び替えバー・Step 3 を非表示にする。

#### 【Step 2】ヒットレコード選択コーナー

Step 1の検索完了後に表示される（ヒット0件の場合は「該当するレコードが見つかりませんでした」メッセージを表示）。

1. **補助操作ボタン**：
   * 「すべて選択」「すべて解除」ボタン（ヒット件数が多い場合の操作性向上）。
2. **ヒットレコード一覧（チェックボックス付き）**：
   * 検索キーワードを含む行が1行以上存在したレコードの `title`（および出典種別バッジ：`ulinker_notes` または `CSVファイル名`）をチェックボックス付きリストで表示する。
   * 表示順はサーバー取得順（`contents_id` 昇順：作成-昇順）を基準とする。
   * **初期状態**：検索完了直後は**すべて未チェック**とする（ユーザーが必要なレコードのみにチェックを入れる運用）。
3. **確定ボタン**：
   * コーナー最下部・中央寄りに **「キーワードを含む行の一覧を表示」ボタン** を配置する（文字色は白 `#FFFFFF`、1件以上チェックされていない場合は非活性）。
   * **押下時の挙動**：
     1. チェックされていたレコードを出力対象リストとして確定し、**Step 3**（およびその直前の並び替えプルダウン）を表示／最新内容へ上書き更新する。
     2. 確定処理と同時に、**Step 2 のチェックボックスはすべて未チェック状態へリセット**する（再選択時の誤重複や手間を防止するため）。

#### 【中間配置】表示順並び替えプルダウンエリア（Step 2 と Step 3 の間）

Step 3 が表示されている間、**Step 2（ヒットレコード選択コーナー）と Step 3（キーワードを含む対象行・出典コーナー）の間**に配置される。

* **UI要素**：ラベル「並び順：」＋セレクトボックス（プルダウン）
* **選択肢**：
  1. `作成-昇順`（`contents_id` 昇順）※**初期値（デフォルト）**
  2. `作成-降順`（`contents_id` 降順）
  3. `タイトル順`（ノートタイトルの辞書順・昇順）
* **連動挙動**：
  * プルダウンの選択値が変更される都度、**Step 3 に表示されているノートブロックの並び順がリアルタイムに切り替わる**。
  * クリップボードコピーおよびTXTダウンロードで出力されるテキストの並び順も、このプルダウンで選択中の順序に連動する。

#### 【Step 3】キーワードを含む対象行・出典コーナー

Step 2の「キーワードを含む行の一覧を表示」ボタン押下後に表示される。

1. **上部アクションボタンバー**：
   * **「表示テキストをコピー」ボタン**：後述の「出力テキストフォーマット（案B）」のプレーンテキストをクリップボード（`navigator.clipboard.writeText`）にコピーし、完了トースト／メッセージを表示する。
   * **「表示テキストをダウンロード」ボタン**：同一のプレーンテキストをUTF-8の `.txt` ファイルとしてブラウザダウンロードさせる。
     * ダウンロードファイル名：`keyword_searched_{yyyyMMdd_HHmmss}.txt`（例：`keyword_searched_20261116_123045.txt`）
2. **抽出結果表示エリア**：
   * 画面上では、該当行内の検索キーワード一致箇所を `<mark class="hl-keyword">...</mark>` でハイライト表示する（XSS防止のためHTMLエスケープ処理と組み合わせて安全に描画する）。
   * 各行の先頭・末尾の空白やタブ（インデント）はトリムせず、元のノートの表現を忠実に保持する。
   * コピーおよびダウンロード時はHTMLタグを含まない純粋なプレーンテキスト（PHP側でアンエスケープ済みの文字列）を出力する。

## 4. データ処理・API設計

### 4.1 エスケープ解除（アンエスケープ）および検索アルゴリズム

既存U-Linkerでは、`commonFunctions.escapeText()` により以下の独自エスケープおよびHTMLエンティティ化が行われている。検索精度と出力可読性を担保するため、**サーバー側（PHP）でレコード取得直後に一括して逆変換（アンエスケープ）を実行**し、フロント側では再変換を行わない。

| 保存時のエスケープ文字列 | 復元後の文字 | 備考 | 
| :--- | :--- | :--- | 
| `&nbsp;` | ` `（半角スペース） | 既存 `escapeText` 独自仕様 | 
| `&com;` | `,`（カンマ） | 既存 `escapeText` 独自仕様（CSV区切り保護用） | 
| `&yen;` | `\`（バックスラッシュ/円記号） | 既存 `escapeText` 独自仕様 | 
| `&copy;` | `©` | 既存 `escapeText` 独自仕様 | 
| `&amp;` / `&lt;` / `&gt;` / `&quot;` / `&#39;` / `&#039;` | `&` / `<` / `>` / `"` / `'` | PHP `htmlspecialchars_decode(..., ENT_QUOTES)` で復元 | 

**【行抽出処理ステップ（サーバー側 PHP）】**

1. **取得順序の統一**：
   * DB（`ulinker_notes`）検索時は `ORDER BY contents_id ASC` でレコードを取得する。
   * CSV（`storage/csv/ulinker_notes*.csv`）検索時は行データを読み込み、`contents_id`（インデックス `0`）の数値昇順でソートした上で走査する（CSVの列インデックス：`contents_id=0`, `title=1`, `note=4`, `publicity=5`, `created_user_id=10`）。
2. **アンエスケープ処理**：取得したレコードの `title` と `note`（本文）に対して上記アンエスケープ処理を実行する。
3. **閲覧権限フィルタ**：4.2節の条件式を適用し、許可されていないレコードをスキップする。
4. **改行正規化・行分割とキーワード判定**：
   * CSV由来等のリテラル文字列（`\r\n`, `\r`, `\n`）および実改行コードを実改行（`\n`）へ正規化し、統一的に1行ごとの配列へ分割する（各行の行頭・行末スペース/タブなどのインデントは忠実に保持）。
   * 各行に対して検索キーワード（1ワード）の部分一致判定（大文字・小文字を区別しない `mb_stripos` による柔軟一致）を行う。
5. **上限打ち切りと重複扱い**：
   * 1行以上ヒットしたレコードのみを抽出対象とし、**選択された全ソースを通算して**指定された「最大取得件数（`limit`）」に達した時点で走査を打ち切る。
   * DBとCSVに同一内容のノートが存在する場合でも、出典（`sourceName`）が異なる別レコードとしてそれぞれリストアップする。

### 4.2 閲覧権限フィルタ仕様（DB・CSV共通統一ルール）

PHPセッションのログインユーザー情報（`$_SESSION['owner_id']`, `$_SESSION['is_teacher']`）に基づき、**DBレコード・CSVレコードの双方に対して同一の基準**で以下の条件式を適用する（CSV側でも `publicity == 2` の講師限定公開を許容する）。

```text
抽出許可条件 :=
    (レコード.created_user_id == $_SESSION['owner_id'])
    OR (レコード.publicity == 1)  // 1: 公開
    OR ($_SESSION['is_teacher'] == 1 AND レコード.publicity == 2)  // 2: 講師にのみ公開
```

### 4.3 Step 3 出力テキストフォーマット仕様（案B：タイトル別グルーピング形式）

画面表示（テキスト構造）、クリップボードコピー、TXTダウンロードのすべてで以下の統一フォーマット（案B）を使用する。並び順は「表示順並び替えプルダウン」の選択状態に従う。

```text
検索キーワード: {検索したワード}

■ {ノートタイトル1}（出典: ulinker_notes）
・{該当行の全文（省略なし・アンエスケープ済み）}
・{該当行の全文（省略なし・アンエスケープ済み）}

■ {ノートタイトル2}（出典: ulinker_notes__{半角英数字の文字列}.csv）
・{該当行の全文（省略なし・アンエスケープ済み）}
```

※先頭の `検索キーワード: {検索したワード}` の直後に空行（1行分のマージン）を設け、以降の各ノートブロック間も空行1行で区切る。

### 4.4 API仕様概要（`server/api/getKeywordLinesList.php`）

既存API群（`getSearchedDataList.php`, `getCsvList.php` 等）の認証・通信方式に準拠する。

* **メソッド**：`POST`（`application/json` または `multipart/form-data`）
* **認証・セキュリティチェック**：
  1. セッションチェック：`$_SESSION['session_string']` および `$_SESSION['owner_id']` が有効であること。
  2. トークンチェック：リクエストパラメータの `token` が半角英数字16文字（`isAlphanumeric16($token)`）であること。
* **リクエストパラメータ**：
  * `token` (string, 必須)：API認証用ワンタイムトークン（半角英数字16文字）
  * `keyword` (string, 必須)：検索キーワード（フロント側で先頭1ワード抽出済みの文字列）
  * `sources` (array, 必須)：検索対象ソース配列（1件以上〜4件以内。例：`["ulinker_notes", "ulinker_notes__{半角英数字の文字列}.csv"]`）
  * `limit` (int, 必須)：最大取得レコード件数（`10` / `50` / `100` / `500`）
* **レスポンスJSON構造**：
  ```json
  {
    "status": "success",
    "keyword": "検索ワード",
    "totalHitRecords": 2,
    "records": [
      {
        "recordKey": "DB_123",
        "contentsId": 123,
        "sourceType": "DB",
        "sourceName": "ulinker_notes",
        "title": "ノートタイトル1",
        "matchedLines": [
          "検索ワードを含む1行目の全文テキスト",
          "検索ワードを含む2行目の全文テキスト"
        ]
      }
    ]
  }
  ```
  ※フロントエンド側の「作成-昇順」「作成-降順」の並び替え処理に使用するため、各レコード要素に数値型の `contentsId` を含めて返却する。
* **エラー時レスポンス**：未ログインまたはトークン不正時（HTTP 401 または `status: "unauthorized"`）、パラメータ不正時（`status: "error"` + エラーメッセージ）。
